# Telegram-бот для онлайн-записи к мастерам (MVP)

Прототип CRM-бота в Telegram: мастер ведёт услуги и расписание, клиент находит мастера и записывается. Код написан с помощью ИИ-инструментов; требования, структура данных и бизнес-логика продуманы мной, подробное ТЗ и UML-схемы лежат в `docs/`.

**Статус:** MVP, в продакшене не развёрнут. Полный исходник (~4 тыс. строк, один файл) не публикую, в репозитории ключевые фрагменты.

## Видео работы

## Что умеет
- Роли «мастер» и «клиент»
- Профиль мастера: описание, фото, геопозиция
- Услуги с ценой и длительностью, недельное расписание
- Запись на свободный слот с учётом длительности услуги
- Поиск мастера (по услуге, по имени, по расстоянию)
- Тарифы для мастеров и оплата через Telegram Payments (тестовый режим провайдера)
- Напоминания о записях и ежедневный план мастера
- Ограничение частоты запросов на пользователя

## Стек
Python, python-telegram-bot (async), PostgreSQL (asyncpg), Telegram Payments API.

## Что смотреть в коде (`code_excerpts/`)
| Файл | О чём |
|---|---|
| `01_database_access.py` | Пул соединений asyncpg, параметризованные SQL-запросы, проверка лимита тарифа |
| `02_payments.py` | Инвойс, pre-checkout, обработка успешного платежа |
| `03_booking_slots.py` | Расчёт свободных слотов с учётом длительности услуги |
| `04_rate_limit_and_jobs.py` | Декоратор rate limit и фоновые напоминания |

Фрагменты не запускаются отдельно: они зависят от остального бота.

## Документация (`docs/`)
Диаграмма классов, варианты использования, диаграмма последовательности записи, компоненты и развёртывание.

## Ограничения и что бы я улучшил
- Весь код в одном файле, нужно разбить на модули
- Состояние диалогов хранится в памяти процесса (после перезапуска теряется), нужен Redis или хранение в БД
- Нет автотестов и миграций схемы БД
- Не развёрнут на сервере; для внешнего использования нужны деплой и политика хранения персональных данных
